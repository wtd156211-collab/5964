# DNS 报文解析与查询构造（受限子集）

我们做内网资产盘点，要自己发查询、解析应答，把域名对应的记录收上来。环境里不让装解析库，想自己写一个。

范围收窄了：只做**查询**和**应答**两类报文，记录类型只做**地址（A）、IPv6 地址（AAAA）、别名（CNAME）、文本（TXT）**四种，不做扩展机制、不做签名、不做区传送。解析这块最麻烦的是名字压缩指针，报文里的名字可能指向前面某个偏移、还可能套好几层，处理不好要么跑飞要么转不出来，这条必须防住、深度也要限。还要能构造查询：给域名和类型生成报文，构造出来的字节要能被标准实现接受，samples 里有期望字节，逐字节对上才算过。坏报文要能诊断：长度不够、指针成环、类型不支持、字节数跟声明对不上，这几类都要报出来，并且说清楚错在哪个偏移。性能上，samples 里那份一万条应答要在几秒内解完。实现只用标准库，测试用 unittest。

仓库里只有这份说明和 samples 里的报文与清单，代码从零写。

## 支持范围

| 项 | 范围 |
| --- | --- |
| 报文类型 | 查询（QR=0）与应答（QR=1），OPCODE 必须为 0（标准查询） |
| 记录类型 | `A`(1)、`CNAME`(5)、`TXT`(16)、`AAAA`(28)，其它一律报不支持 |
| CLASS | 只做 `IN`(1) |
| 段 | 只解析 QUESTION 与 ANSWER；`NSCOUNT` 与 `ARCOUNT` 必须为 0，否则报 `UNSUPPORTED_SECTION` |
| 压缩指针 | 支持（见下一节），只用在名字上 |

不做：EDNS0/OPT 扩展、DNSSEC 相关记录与字段、AXFR/IXFR 区传送、动态更新、TCP 长度前缀、多问题/多段混合的复杂报文。

## 名字与压缩指针规则

名字是一串「标签 + 结束符」：每个标签首字节是长度（1–63），后面跟内容；以长度 0 结束。名字总长度（拼出来的域名）不得超过 255 字节。

压缩指针：首字节高两位是 `11`（即 `0xC0`）时，这个字节与下一字节合成 14 位偏移 `((b1 & 0x3F) << 8) | b2`，指向报文里**另一个名字的位置**。规则写死成下面几条：

1. **必须严格向前指**：指针目标偏移必须**小于**指针自身所在的偏移，否则报 `BAD_POINTER`（这条本身就堵掉了自指与互指的环）；
2. **深度上限 8 层**：一次名字解析里最多跟随 8 层指针，超过报 `POINTER_LOOP`（偏移取超过的那一层指针）；
3. 指针目标必须落在报文范围内，否则报 `BAD_POINTER`；
4. 首字节高两位是 `10` 或 `01` 的保留形式，一律报 `BAD_POINTER`；
5. 解析完名字后，**游标停在指针占用的两个字节之后**（后续记录的 TYPE/CLASS 从这里继续读），不要跳到指针目标的末尾；
6. 名字里允许大小写混合，解析结果**原样保留**报文里的大小写。

## 构造查询

输入是域名与记录类型，输出是报文字节：

- 头部：`ID` 由调用方指定（不指定时用 0）、`QR=0`、`OPCODE=0`、`AA=TC=RA=0`、`RD` 由调用方指定（默认 1）、`Z=0`、`RCODE=0`；
- `QDCOUNT=1`，`ANCOUNT=NSCOUNT=ARCOUNT=0`；
- QNAME 按标签编码，**不做压缩**；
- QTYPE 用类型编号，QCLASS = `IN`(1)；
- 域名允许末尾带点（`example.com.` 与 `example.com` 等价），编码时去掉末尾点；空标签（连续两个点）或空域名、标签超过 63 字节、整体超过 255 字节都算非法输入。

**允许变化的字段只有两个：`ID` 与 `RD` 标志**，其余字节必须与 samples 里的期望字节**逐字节相同**。期望字节按十六进制写在 `samples/queries.json` 里，就是验收标准。

## 输出结构

解析结果逐行输出，行尾 LF。前四行是头部，接着是问题与每条回答：

```text
id=4660
flags=0x8180
qdcount=1
ancount=2
q,example.com,A,IN
a,example.com,A,IN,300,192.0.2.1
a,example.com,AAAA,IN,300,2001:db8::1
```

- `id` 十进制，`flags` 是 4 位小写十六进制（补零）；
- `q,<名字>,<类型>,<CLASS>`；`a,<名字>,<类型>,<CLASS>,<TTL>,<值>`；
- `A` 的值写成点分十进制；
- `AAAA` 的值按 RFC 5952 的零压缩写（小写、最长的一段零压缩成 `::`、等长取靠前的那段）；
- `CNAME` 的值是解压后的域名，保留原大小写；
- `TXT` 的值是各个字符串段**直接拼接**后的文本，用 JSON 字符串形式输出（带双引号，内部按 JSON 转义）。

出错时只输出一行：`error,<错误码>,<偏移>`，偏移是从报文开头算的**字节偏移**（从 0 开始）。

## 错误码

| 错误码 | 含义 | 偏移指向 |
| --- | --- | --- |
| `TRUNCATED` | 长度不够：需要读 N 字节但报文已经结束 | 缺失内容的起始位置 |
| `POINTER_LOOP` | 指针层数超过 8 层 | 超过的那一层指针 |
| `BAD_POINTER` | 指针向后指、越界，或用了保留形式（`01`/`10`） | 出问题的那个字节 |
| `UNSUPPORTED_TYPE` | 记录类型不在四种里 | 该记录的 TYPE 字段起始 |
| `UNSUPPORTED_CLASS` | CLASS 不是 `IN` | 该记录的 CLASS 字段起始 |
| `UNSUPPORTED_SECTION` | `NSCOUNT` 或 `ARCOUNT` 不为 0 | 偏移固定为 8 |
| `LENGTH_MISMATCH` | RDATA 的声明长度与实际解析出的字节数对不上 | 该记录的 RDLENGTH 字段起始 |
| `NAME_TOO_LONG` | 名字拼出来超过 255 字节 | 该名字的起始位置 |

诊断顺序：先头部长度与段计数，再按报文顺序逐个问题、逐条回答解析，遇到第一个问题就返回。

## 性能与确定性

- `samples/bulk.bin` 里是一万条应答（长度前缀流，见下），要在 **几秒**内解完；
- 同一份报文跑两遍，输出必须逐字节一样；
- 解析走一遍字节数组即可，不要为每个标签反复复制整段报文。

## 样例

```text
samples/queries.json     4 条查询的定义 + 期望字节（十六进制）
samples/responses.json   3 条应答：期望解析结果（逐行）+ 报文十六进制
samples/broken.json      4 条坏报文 + 期望 error 行
samples/bulk.bin         一万条应答，格式是「4 字节大端长度 + 报文字节」重复
samples/bulk.expected.txt 批量文件的期望统计（消息数、回答条数、各类型计数）
```

三条应答覆盖：A 与 AAAA 并列、名字压缩指针指回问题里的名字；CNAME 的 RDATA 里再带一个域名（嵌套解析）；大小写混合的名字。四条坏报文分别命中 `TRUNCATED`、`POINTER_LOOP`（10 层指针链）、`UNSUPPORTED_TYPE`、`LENGTH_MISMATCH`，偏移各不相同。

## 实现说明

代码分三个文件，全部只用标准库：

- `dnsmsg.py`：解析与构造的核心。`build_query()` 构造查询，`parse_message()` /
  `parse_message_records()` 解析报文，`format_message()` 直接给出输出文本，
  `bulk_stats()` 统计批量流；诊断错误统一抛 `DNSError(code, offset)`。
- `dnstool.py`：命令行入口，子命令 `query`（输出十六进制）、`parse`（十六进制
  或 `--file`）、`bulk`（统计长度前缀流）。
- `test_dnsmsg.py`：unittest 测试，直接以 samples 里的期望字节、期望行、
  期望 error 行做验收，另补了保留形式指针、自指指针、非 IN 类、超长名字等用例。

### 名字与指针的单趟处理

`parse_name()` 只走一遍字节数组：游标沿「长度 + 标签」前进，把标签切片追加到
一个列表（只切标签本身，不复制整段报文，完整域名只在最后 `join` 一次）。
遇到 `0xC0` 指针时记住「第一次跳转前的位置 + 2」作为返回值——这就是规则第 5
条要求的游标停点，之后跳到目标偏移继续扫，不再回头。

防跑飞靠两条同时生效：

1. **严格向前**：指针目标必须小于指针自身偏移，自指、互指、向后指一律
   `BAD_POINTER`，环在结构上就不可能构成；
2. **深度上限**：每跟随一层指针计数加一，要跟随第 9 层时在那一层指针的偏移
   抛 `POINTER_LOOP`（上限 8 层）。就算将来有人改松第 1 条，层数上限也能兜底。

越界防护：每次读字节前先经 `_read()` 检查 `offset + n <= len(msg)`，不够就
在读取起点抛 `TRUNCATED`；指针目标虽然必然小于自身偏移（也就必然在报文内），
仍显式校验一次范围。`01`/`10` 保留形式在标签分派时直接 `BAD_POINTER`。

### 长度一致性

RDATA 先按 `RDLENGTH` 整体确认在报文内（不够报 `TRUNCATED`），再按类型校验
实耗字节数：A 必须恰好 4、AAAA 恰好 16；CNAME 解压后游标推进量必须等于
`RDLENGTH`；TXT 逐段累加「1 + 段长」，任何一段越过 RDATA 边界即不符。不符
统一在 `RDLENGTH` 字段起点抛 `LENGTH_MISMATCH`。

### 批量文件

`iter_bulk()` 按「4 字节大端长度 + 报文」切流，逐条产出报文交给
`parse_message_records()`，只累计计数不拼输出字符串。`samples/bulk.bin`
一万条应答在本机约 0.05 秒解完，远低于几秒的要求；同一报文重复解析输出
逐字节一致（无随机、无时间、无字典序依赖的输出路径）。

运行测试：`python3 -m unittest -v test_dnsmsg`
